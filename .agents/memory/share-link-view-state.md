---
name: Share-link view-state restoration
description: How the /s/{shortId} share-link feature captures and restores per-page view-state, and the races/gaps to watch.
---

Short branded links (`/s/{shortId}`) are server-backed: `ShareLink` model stores an opaque `state_json` per page; `ShareResolver` page fetches `/api/share-links/{id}`, then redirects to the real page path with the state object flattened into query params. The target page reads those params in mount effects.

**Rule:** Each shared page exposes a `getShareState()` returning a plain object whose keys are the query-param names the page's own mount effects read back. Keep the serialize keys and the restore keys in lockstep — a key added to getShareState with no matching restore effect silently does nothing, AND a restore effect that requires two keys together will silently drop a state that only has one of them.

**Why / gap that got a review rejection:** War Room serialized `tile` always but `dpath` only when a drill path existed. Its restore effect early-returned unless BOTH `tile` and `dpath` were present, so a tile-only share never restored the active tile ("full view state" requirement violated). Fix: restore the tile whenever `tile` is valid, treat `dpath` as optional (default depth 1), only decode `dpath` when present. Lesson: when one serialized field is conditional, the restore must not hard-require it alongside another.

**Race to watch:** Some pages restore per-entity state from localStorage/persistent-state on an id-change effect. A shared link supplying that same state via URL will be overwritten by the local restore unless you guard the first run (init from URL in `useState(() => ...)` + a one-shot ref that makes the local restore bail on its first run when URL params were present).

**Why / second review rejection — "exact state" must include DEFAULT values:** "Restore exactly what the sender saw" fails for any field that is (a) persisted on the recipient's side AND (b) only serialized when non-default. If the sender shares a default (doctrine closed, members at 500, empty search), getShareState omitted it, so the recipient's stale persisted value won. Two-part fix per shareable+persisted field: (1) serialize the value ALWAYS, not only when non-default — and use a representation that survives the resolver (the resolver DROPS null/undefined/empty-string, so emit "0"/"1" booleans and raw numbers, never ""); (2) on restore, treat the URL as authoritative even for defaults — pick one always-emitted param as the "this is a shared link" signal and, when present, clear/override any locally-persisted competing field (including clearing it when the share omitted it). Fields that are plain non-persisted useState don't need this — the recipient already starts at the same default.

**Persist-vs-restore ordering:** when a page both persists live state AND restores it via an async mount effect, the persist effect will clobber the saved value before restore runs unless gated. **Why:** effects flush in order and the async restore's state writes haven't applied yet, so persist reads stale defaults and overwrites storage. **How to apply:** gate persistence behind a "restore settled" ref, have restore capture the saved object as a closure arg before any write, scope the saved trail to its owning entity (e.g. company+tile) and bail restore on mismatch, and skip restore when a share-link marker is in the URL so share restoration wins. Also reset the saved trail in EVERY teardown path (clear-company as well as switch/close-tile), not just the obvious one.

**Email safety:** the share email HTML interpolates the user-provided `note`. Always `html.escape()` it before insertion (server is `backend/routers/share_links.py`). The `url` is server-generated so it is trusted.

**How to apply:** When adding share support to a new page: (1) add `getShareState()`; (2) add/extend a mount effect that reads each key, requiring no two keys to be co-present unless both are always serialized together; (3) if the page already restores the same fields from another source (localStorage/persistent-state), make the shared URL win on first load; (4) register the page slug in backend `VALID_PAGES` and resolver `PAGE_PATHS`, and add it to ShareMenu's `SharePage` type. The `/s/:shortId` resolver route is public so it resolves before the auth-gated page mounts; the pages themselves stay auth-gated.
